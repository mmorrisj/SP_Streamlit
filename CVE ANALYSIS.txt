No XSLT transformations, XSL stylesheets, or xml2 extension usage exist anywhere in the application — the xml2 extension is not loaded (CREATE EXTENSION xml2 does not appear in any initialization script), and no XSLT processing is ever triggered. The library is an unremovable transitive dependency of the postgresql-16 package, and its vulnerable code paths are never invoked at runtime.
CVE-2025-5278 - Not applicable — CVE-2025-5278 is a heap buffer under-read in GNU coreutils' sort utility where the begfield() function performs unsafe pointer arithmetic when processing the traditional key specification syntax (+POS1) with UINTMAX_MAX as the character position, causing a pointer to reference one byte before the allocated buffer. Exploitation requires a user to run sort with a specially crafted command-line key argument — the vulnerability is debated as a regular bug rather than a security issue since it requires direct control over sort's command-line arguments. No sort commands execute at runtime in the container — the only running process is the PostgreSQL server, which has its own internal sort implementation for query processing and does not invoke GNU sort. The coreutils package is an unremovable base-image dependency, and the vulnerable sort begfield() code path is never executed at runtime.
CVE-2025-6141 - Not applicable — CVE-2025-6141 is a stack-based buffer overflow in GNU ncurses' postprocess_termcap() function in tinfo/parse_entry.c, triggered when processing a maliciously crafted termcap entry. Exploitation requires local access and the ability to supply a crafted termcap/terminfo database to a program linked against ncurses. The libncursesw6 and libtinfo6 libraries are present in the image as transitive dependencies of base-image utilities (e.g., bash, less, util-linux) that provide terminal handling. No interactive terminal sessions, TUI applications, or termcap/terminfo database processing occurs at runtime in the container — the only running process is the PostgreSQL server, which communicates via the wire protocol on port 5432 and does not use ncurses for terminal rendering. No user-supplied termcap entries can reach the vulnerable postprocess_termcap() function. Debian classifies this as <no-dsa> (minor issue). The libraries are unremovable transitive dependencies of the base image, and the vulnerable termcap-parsing code path is never invoked at runtime.
CVE-2025-8732 - Not applicable — CVE-2025-8732 is an uncontrolled recursion flaw in libxml2's xmlParseSGMLCatalog() function within the xmlcatalog component, where processing a maliciously crafted SGML catalog file causes unbounded recursion and a crash. The libxml2 maintainer states the security impact is "negligible since the vulnerability requires the use of untrusted SGML catalogs, which is not a recommended practice." As with CVE-2026-0990, libxml2 is present because postgresql-16 is compiled with --with-libxml for SQL/XML standard support. PostgreSQL's XML functionality (xml data type, xpath(), xmlparse()) parses XML documents — it does not load or process SGML catalog files. No XML_CATALOG_FILES environment variable, /etc/xml/catalog, SGML catalog configuration, or xmlcatalog invocation exists in the container, so the xmlParseSGMLCatalog() code path cannot be reached. The library is an unremovable transitive dependency of the postgresql-16 package, and its SGML catalog-parsing code path is never invoked at runtime.
