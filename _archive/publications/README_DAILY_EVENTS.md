# Daily Event Extraction

Extract unique events with materiality assessment from existing daily publication JSON files.

## Overview

This is **Part 1 of the Hasty Publication Event Pipeline**. It processes your already-generated daily publication JSON files to extract:

- **Unique events** (no duplicate coverage)
- **Materiality scores** (0.0-10.0, measuring concrete vs symbolic nature)
- **Brief event summaries** (2-3 sentences)
- **Key entities** (persons, organizations, companies, locations)
- **Full source tracking** (doc_ids with ATOM search URLs)

**After daily extraction, see [README_CONSOLIDATION.md](README_CONSOLIDATION.md) for hierarchical consolidation into weekly/monthly/overall summaries.**

**Everything stays within the `publications/` folder - no mixing with main pipeline.**

## Materiality Scoring

The script uses the materiality metric from your main pipeline, measuring **concrete vs symbolic** nature:

| Score | Category | Examples |
|-------|----------|----------|
| **9.0-10.0** | Highly Material | Signed treaties, construction projects, financial commitments, troop deployments |
| **7.0-8.9** | Substantial | MoUs with implementation plans, trade deals with figures, joint ventures |
| **5.0-6.9** | Moderate | High-level visits with deliverables, working groups established |
| **3.0-4.9** | Limited | Statements of intent, dialogue mechanisms, cultural exchanges |
| **0.0-2.9** | Symbolic | Rhetoric, expressions of friendship, vague commitments |

**Note**: Materiality ≠ Importance. A symbolic statement from a world leader might be very important politically, but has low materiality (no concrete action).

## Features

### ✅ Unique Events Only
The LLM deduplicates - if 3 documents cover the same event, it's listed once with all 3 doc_ids.

### ✅ Materiality Assessment
Each event gets a precise materiality score with justification, using the same metric as your main pipeline.

### ✅ Entity Extraction
Automatically identifies:
- **Persons**: Government officials, diplomats, business leaders (with roles)
- **Organizations**: Govt agencies, intl organizations, NGOs (with types)
- **Companies**: Corporations, SOEs, firms (with sectors)
- **Locations**: Cities, facilities, infrastructure (with types)

### ✅ Source Tracking
Every event and entity links back to source documents via `doc_ids`.

### ✅ ATOM Search Hyperlinks
Each event includes an automatically generated `atom_search_url` that opens all source documents in ATOM search. Click the link to instantly view all original documents for verification.

Example: `https://atom.opensource.gov/searches?ss=id%3A(%22doc1%22+OR+%22doc2%22)&go=1`

### ✅ Self-Contained
All inputs and outputs stay in `publications/` - no mixing with main pipeline data.

### 2. Materiality Analysis
Identify which events are concrete actions vs rhetoric.

```python
import json
from pathlib import Path

# Load all June events
events_dir = Path("publications/events/China/daily")
high_materiality = []

for file in events_dir.glob("2025-06-*_events.json"):
    data = json.load(open(file))
    for event in data['events']:
        if event['materiality']['score'] >= 8.0:
            high_materiality.append(event)

print(f"High materiality events: {len(high_materiality)}")
```

### 3. Entity Network Analysis
Build relationship graphs of actors.

```python
from collections import defaultdict

# Track which persons appear together
person_cooccurrence = defaultdict(set)

for file in events_dir.glob("*_events.json"):
    data = json.load(open(file))
    for event in data['events']:
        persons = [p['name'] for p in event['entities']['persons']]
        for p1 in persons:
            for p2 in persons:
                if p1 != p2:
                    person_cooccurrence[p1].add(p2)
```

### 4. Source Document Lookup
Trace events back to original documents using ATOM search URLs.

```python
# Find all source documents for a specific event type and get ATOM URLs
for file in events_dir.glob("*_events.json"):
    data = json.load(open(file))
    for event in data['events']:
        if 'nuclear' in event['event_name'].lower():
            print(f"Event: {event['event_name']}")
            print(f"Doc IDs: {event['source_doc_ids']}")
            print(f"ATOM Search: {event['atom_search_url']}")
            print()
```

**Result**: Click the `atom_search_url` to instantly open all source documents in ATOM for verification.

## Troubleshooting

### No input files found
```
⊘ No file for 2025-06-01
```

**Solution**: Ensure daily publication JSON files exist at `publications/{Country}/daily/{Date}.json`

### LLM errors
```
✗ Error calling LLM for 2025-06-01
```

**Possible causes**:
- API key issues (check `CLAUDE_KEY` in `.env`)
- Network connectivity
- Azure OpenAI rate limits

**Solution**: Check `shared/config/config.yaml` for model settings.

### Empty events arrays
```
✓ Extracted 0 unique events (Date: 2025-06-01)
```

**Possible reasons**:
- Day genuinely had no significant events (routine news only)
- Input file has very limited content
- LLM determined nothing met uniqueness threshold

Review the source `publications/{Country}/daily/{Date}.json` to verify.
